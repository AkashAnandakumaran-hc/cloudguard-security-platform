# CloudGuard — IaC Security Posture Validation & CI/CD Security Gate

CloudGuard is a shift-left infrastructure security project focused on identifying risky cloud configurations before deployment.

Terraform configurations are statically analyzed with Checkov, while a Python risk engine converts raw findings into severity classifications, remediation priorities, and a weighted security posture score.

A GitHub Actions workflow evaluates the remediated infrastructure state and fails the security check when CRITICAL or HIGH findings remain. The intentionally insecure configuration is maintained separately as a reproducible baseline for testing and comparison.

## Results

The results below were generated by running Checkov against the Terraform configurations included in this repository.

| Metric | Before | After |
|---|---:|---:|
| Checks failed | 27 | 9 |
| Checks passed | 10 | 45 |
| CRITICAL findings | 11 | 0 |
| HIGH findings | 7 | 0 |
| Posture score | 11 / 100 | 96 / 100 |

The remediation eliminated all CRITICAL and HIGH findings identified by the project's risk model.

The 9 remaining findings consist of lower-priority controls that are treated as remediation backlog rather than CI-blocking conditions.

Raw Checkov output and generated posture reports are available under `reports/`.

## Security Scenarios

The intentionally insecure baseline contains several common cloud infrastructure risks, including:

- S3 public-access protections disabled
- SSH exposed to `0.0.0.0/0`
- Overly permissive IAM permissions
- Wildcard IAM actions and resources
- Unencrypted EBS storage
- Missing S3 access logging
- Unrestricted network egress

The remediated configuration applies stronger security controls and reduces all CRITICAL and HIGH findings to zero.

## Python Risk Engine

Checkov provides the underlying infrastructure security findings.

The Python risk engine adds a project-specific decision layer that:

- Maps findings to severity
- Assigns remediation priorities
- Calculates a weighted 0–100 posture score
- Produces JSON and Markdown posture reports
- Highlights findings requiring immediate attention

The weighting intentionally gives greater importance to CRITICAL and HIGH findings rather than treating every scanner result equally.

## CI/CD Security Gate

The GitHub Actions workflow provides automated security validation for the target Terraform configuration.

The workflow:

1. Checks out the repository
2. Installs Checkov
3. Scans the Terraform configuration
4. Processes the findings through the Python risk engine
5. Generates a posture report
6. Fails the CI security check if any CRITICAL or HIGH findings remain

MEDIUM and LOW findings remain visible for remediation tracking but do not fail the security gate.

A repository ruleset or branch-protection rule can additionally require this status check before allowing a merge.

## Policy as Code

The `policies/` directory contains Rego examples representing organization-level security controls around:

- Public network exposure
- Storage encryption
- IAM privilege boundaries

These Rego policies currently serve as policy-as-code examples and are **not directly connected to the active CI/CD enforcement path**.

Current automated validation is performed through Checkov and the Python risk engine.

## Threat Modeling

The project includes a lightweight STRIDE-based threat model covering the infrastructure represented in the Terraform configuration.

Examples include:

- Public object-storage exposure
- Administrative-port exposure
- Excessive IAM privilege
- Unrestricted outbound traffic
- Unencrypted block storage
- Missing audit visibility

Each scenario is mapped to a corresponding security control and validation check.

See `docs/threat-model.md` for details.

## Cost and Scope

The project can be reproduced without deploying cloud infrastructure.

- No AWS resources are provisioned
- No Azure resources are provisioned
- No AWS credentials are required for the static scans
- Terraform configurations are analyzed locally
- Cloud deployment is intentionally outside the scope of the project

## Run Locally

Install Checkov:

```bash
python -m pip install checkov
```

Scan the intentionally insecure baseline:

```bash
python -m checkov.main -d infrastructure/insecure --framework terraform
```

Scan the remediated configuration:

```bash
python -m checkov.main -d infrastructure/secure --framework terraform
```

Generate the baseline posture report from the included Checkov JSON:

```bash
python automation/risk_engine.py reports/before.json \
  --label "Before" \
  --out reports/before_posture.json \
  --md reports/before_posture.md
```

Generate the remediated posture report:

```bash
python automation/risk_engine.py reports/after.json \
  --label "After" \
  --out reports/after_posture.json \
  --md reports/after_posture.md
```
